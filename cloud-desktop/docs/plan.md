## Що перевірено під час розробки

* 34 автотести (`portal/tests`): вхід, ролі, ліміти, повний цикл столу, автовимкнення, проксі-доступ, файли,
  захист від `../` і символьних посилань, квоти, здача й оцінювання, шаблони, адміністрування, параметри Docker.
* Наскрізна перевірка з реальним Docker: портал (`CD_DRIVER=docker`) + Nginx з HTTPS + `kasmweb/ubuntu-jammy-desktop`:
  стіл стартує приблизно за 2–3 с після створення контейнера; KasmVNC відкривається в порталі, WebSocket
  `wss://…/desktop/<id>/websockify` підключається; інший студент отримує 403; пауза, зупинка, продовження і
  скидання працюють; файл у `~/Мої_файли` переживає скидання; контейнери в мережі `cd_desktops` не бачать один одного;
  ліміти RAM/CPU/кількості процесів застосовано.
* Образ `college/mysql-desktop` зібрано й перевірено: MySQL стартує від користувача столу, вхід `student/student`,
  база `college`; дані зберігаються після «Зупинити → Запустити» і очищаються після «Скинути».
  Під час перевірки виправлено: застарілий ключ стороннього apt-репозиторію в базовому образі Kasm ламав збірку;
  каталог даних MySQL не може мати назву з крапкою на початку; Kasm перезапускає `custom_startup.sh`, тому потрібне блокування.
* Образ `college/dev-desktop` побудований за тією ж схемою, але на справжньому сервері ще не збирався (🧪).

## Що показати на захисті

1. Вхід з телефону або слабкого ноутбука → запуск Ubuntu і Kali.
2. Зламати середовище (напр. `rm -rf ~/.config`) → **Скинути** → усе працює, файли в `Мої_файли` на місці.
3. Здати роботу зі столу → викладач бачить її, оцінює, студент бачить оцінку.
4. Викладач підключається до столу студента; запис у журналі.
5. Панель навантаження: скільки столів працює, пам'ять, CPU; результати тесту навантаження.
