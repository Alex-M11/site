**Баги, знайдені під час тестування і виправлені:**

1. Перевірка готовності столу йшла до KasmVNC без пароля → після 5 опитувань KasmVNC заносив адресу Nginx у чорний список,
   і всі (студент, викладач) втрачали доступ до столу. Тепер перевірка йде з паролем столу.
2. Якщо портал створив мережу столів раніше за `firewall.sh`, правила ізоляції мовчки не діяли (інше ім'я мосту).
   Тепер і портал, і скрипт створюють міст `cd-desktops`, а скрипт перестворює неправильну мережу.
3. Фонове обслуговування (автовимкнення!) падало щохвилини через неіснуючий параметр Docker SDK у вимірюванні диска.
4. «Пауза» давала 500, коли cgroup не встигав «заморозити» процеси; тепер є повторні спроби і зрозуміле повідомлення,
   а всі помилки Docker перетворюються на повідомлення для користувача.
5. Прихований iframe тримав старе з'єднання KasmVNC після паузи/зупинки/зміни режиму.
6. Ліміт входу в Nginx (10/хв з IP) не дав би увійти групі, що сидить за одним NAT; тепер точний ліміт — у порталі.
7. Збірка образів падала через застарілий ключ стороннього apt-репозиторію в образі Kasm; MySQL не стартував
   (каталог даних з крапкою, подвійний запуск скрипта Kasm); Node.js у dev-образі був v12.
8. `loadtest.py` не працював з обов'язковою зміною тимчасового пароля; node-exporter не стартував без shared mount;
   порожні панелі Grafana; права файлів бекапу 644; модальні вікна не закривалися Esc; сира сторінка 502 під час оновлення.

## Результати тесту навантаження

Тестова машина: 4 ядра, 16 ГБ RAM (не сервер коледжу — повторіть тест на ньому). Столи «Ubuntu 22.04» через Nginx.

| Столів одночасно | Успішно | Медіана до готовності | Максимум | RAM на порожній стіл | Пік load average |
|---|---|---|---|---|---|
| 10 | 10/10 | 6,7 с | 7,0 с | ≈0,23 ГБ | 10,5 |
| 20 | 20/20 | 12,1 с | 14,6 с | ≈0,22 ГБ | 64,6 (момент старту) |

Стіл із відкритими Firefox і VS Code займає ≈0,8 ГБ, тож реальний орієнтир — **1–1,5 ГБ на активний стіл**:
для групи з 20 студентів потрібно 24–32 ГБ RAM. Під час одночасного старту 20 столів 4 ядра перевантажені
(старт займає до 15 с); для пари рекомендовано 8+ ядер.

## Що показати на захисті

1. Вхід з телефону або слабкого ноутбука → запуск Ubuntu і Kali.
2. Зламати середовище (напр. `rm -rf ~/.config`) → **Скинути** → усе працює, файли в `Мої_файли` на місці.
3. Здати роботу зі столу → викладач бачить її, оцінює, студент бачить оцінку.
4. Викладач підключається до столу студента; запис у журналі.
5. Панель навантаження: скільки столів працює, пам'ять, CPU; результати тесту навантаження.
