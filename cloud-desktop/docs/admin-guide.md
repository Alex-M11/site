# Інструкція адміністратора

## 1. Сервер

| Сценарій | Одночасних столів | RAM | CPU | Диск |
|---|---|---|---|---|
| Тест вдома | 2–3 | 8 ГБ | 4 ядра | 100 ГБ |
| Одна група на парі | 15–20 | 32 ГБ | 8 ядер | 500 ГБ |
| Кілька груп одночасно | 40+ | 64 ГБ і більше | 16 ядер | 1 ТБ |

Числа орієнтовні — уточніть їх тестом навантаження (розділ 7). Образи столів займають 3–6 ГБ кожен,
решта диска — файли студентів (квота × кількість студентів) і резервні копії.

ОС: **Ubuntu Server 22.04 або 24.04**. Для пілоту підійде старий ПК або віртуальна машина з увімкненою вкладеною віртуалізацією.

## 2. Встановлення

```bash
sudo apt install -y git
sudo git clone <репозиторій> /opt/src && sudo cp -r /opt/src/cloud-desktop /opt/cloud-desktop
cd /opt/cloud-desktop
sudo bash scripts/install-server.sh
```

Скрипт ставить Docker, вмикає брандмауер (відкриті лише 22, 80, 443), створює мережу столів з ізоляцією,
папку `/srv/cloud-desktop` і файл `.env` з випадковими паролями.

Відредагуйте `.env`:

* `CD_DOMAIN` — адреса порталу (напр. `desk.college.edu.ua` або IP у локальній мережі);
* `CD_ADMIN_PASSWORD` — пароль першого адміністратора;
* `CD_KASM_TAG` — тег образів Kasm (перевірте актуальний на Docker Hub: `kasmweb/ubuntu-jammy-desktop`).

Далі:

```bash
sudo bash scripts/build-images.sh        # завантажити й зібрати образи столів
sudo bash scripts/selfsigned-cert.sh     # тимчасовий сертифікат
sudo docker compose up -d --build
sudo docker compose logs -f portal       # перевірити, що портал стартував
```

Сертифікат Let's Encrypt (потрібні публічний домен і відкритий порт 80):

```bash
sudo bash scripts/letsencrypt.sh admin@college.edu.ua
# автооновлення, crontab -e (root):
17 3 * * 1  cd /opt/cloud-desktop && bash scripts/letsencrypt.sh renew
```

Для пар у локальній мережі коледжу без публічного домену залиште самопідписаний сертифікат і один раз
підтвердіть виняток у браузерах аудиторії (або роздайте сертифікат через групову політику).

## 3. Перше налаштування в порталі

1. Увійдіть як `admin`, змініть пароль у **Профілі**.
2. **Групи → + Група** (напр. `КН-21`).
3. **Користувачі → Імпорт CSV** — список студентів групи:
   ```csv
   username,full_name,password,role,group
   ivan.petrenko,Петренко Іван,Start2026a,student,КН-21
   olena.koval,Коваль Олена,Start2026b,student,КН-21
   o.ivanenko,Іваненко Олена Петрівна,Teach2026x,teacher,
   ```
   Групи, яких немає, створюються автоматично. Логін — малі латинські літери, цифри, `.`, `-`, `_`.
4. Відкрийте картку викладача і позначте **Групи викладача**.
5. **Ліміти й образи** — перевірте ліміти (розділ 4).

## 4. Ліміти

| Налаштування | За замовчуванням | Пояснення |
|---|---|---|
| Максимум активних столів | 20 | Запущені + на паузі. Формула: (RAM сервера − 4 ГБ) / 1,5 ГБ |
| Столів на користувача | 2 | Щоб один студент не займав кілька місць |
| Автовимкнення при простої | 30 хв | Стіл без дій зупиняється, файли зберігаються |
| Квота диска студента | 2048 МБ | Можна змінити окремому користувачу в його картці |
| Максимум CPU / RAM шаблону | 2 CPU / 4096 МБ | Більше викладач не зможе задати |

Квота перевіряється при завантаженні через портал. Щоб жорстко обмежити запис **зсередини столу**,
розмістіть `/srv/cloud-desktop` на XFS з `prjquota` і задайте квоти проєктів (`xfs_quota`) для `home/<логін>`.
Щоб обмежити розмір самого контейнера, Docker має працювати на XFS з `pquota`; тоді задайте `CD_CONTAINER_DISK_SIZE=10G`.

**Каталог образів** (JSON) — які образи дозволено викладачам. Додати новий образ: зберіть його (`docker build …`)
або завантажте (`docker pull …`) на сервер і допишіть у каталог:

```json
{"image": "kasmweb/kali-rolling-desktop:1.17.0", "label": "Kali Linux", "os": "kali"}
```

## 5. Безпека

Що вже зроблено:

* один контейнер на студента, користувач усередині — не root, `no-new-privileges`, ліміти CPU, RAM, кількості процесів;
* порти столів відкриті тільки на `127.0.0.1`; до столу можна дістатися лише через Nginx після перевірки порталом
  (власник, викладач його групи або адміністратор);
* пароль VNC генерується для кожного столу і не потрапляє в браузер — його підставляє Nginx;
* мережа `cd_desktops` без зв'язку між контейнерами; `scripts/firewall.sh` забороняє столам доступ до сервера
  й до приватних мереж коледжу (10.x, 172.16–31.x, 192.168.x) та SMTP. Навчальну підмережу можна дозволити:
  `LAB_ALLOW="10.50.0.0/24" sudo -E bash scripts/firewall.sh`;
* HTTPS, HSTS, паролі — лише хеш PBKDF2-SHA256, обмеження спроб входу (5 за 5 хв на логін/IP + ліміт у Nginx),
  JWT у HttpOnly-cookie, захист від CSRF;
* журнал: входи (і невдалі), запуски, скидання, підключення викладачів, здачі робіт, зміни налаштувань.

Важливо знати:

* Портал має доступ до `docker.sock`, тобто фактично root на сервері. Не встановлюйте на сервер нічого зайвого,
  оновлюйте систему (`unattended-upgrades`) і обмежте SSH (ключі, без пароля).
* Не публікуйте порт 8000 і 3306 назовні — вони слухають лише `127.0.0.1`.
* Kali Linux містить інструменти атак: затвердьте правила користування і нагадайте про них студентам.
* Регулярно оновлюйте образи (`scripts/build-images.sh`) — у них виходять виправлення безпеки.

## 6. Резервні копії

```bash
sudo bash scripts/backup.sh        # БД + файли студентів + здані роботи → /srv/cloud-desktop/backups
# щоночі (crontab -e, root):
30 2 * * *  cd /opt/cloud-desktop && bash scripts/backup.sh >> /var/log/cd-backup.log 2>&1
```

Копіюйте каталог `backups` на інший диск або сервер (rsync, зовнішній диск) — копія на тому ж диску не врятує
при його поломці. Як відновити — в кінці `scripts/backup.sh`.

## 7. Тест навантаження (тиждень 7)

```bash
pip install httpx
python3 scripts/loadtest.py --url https://localhost --insecure --password 'пароль-адміна' \
    --students 20 --template "Ubuntu 22.04" --hold 120
```

Скрипт створить студентів `loadtest01…`, одночасно запустить їм столи і виведе: скільки запустилося,
час до готовності, скільки пам'яті зайняв один стіл, навантаження CPU. Перед тестом підніміть ліміт
«Максимум активних столів». Результати запишіть у [plan.md](plan.md) і виставте реальні ліміти.

## 8. Моніторинг (пізніше)

```bash
sudo docker compose --profile monitoring up -d
```

* Prometheus збирає метрики порталу (`cd_active_sessions`, `cd_sessions{status}`, `cd_logins_24h`) і сервера (node-exporter).
* Grafana: `https://<домен>/grafana/`, логін `admin`, пароль `GRAFANA_PASSWORD` з `.env`. Джерело Prometheus уже підключено;
  імпортуйте дашборд «Node Exporter Full» (ID 1860) і додайте панель з `cd_active_sessions`.

## 9. Обслуговування

| Задача | Команда |
|---|---|
| Логи порталу | `docker compose logs -f portal` |
| Оновити портал | `git pull && docker compose up -d --build portal` |
| Список столів | `docker ps --filter label=cloud-desktop.managed=true` |
| Зупинити всі столи (напр. перед оновленням) | у порталі **Навантаження → Зупинити** або `docker stop $(docker ps -q --filter label=cloud-desktop.managed=true)` |
| Видалити файли студента після відрахування | спершу бекап, потім `rm -r /srv/cloud-desktop/home/<логін>` |
| Скинути пароль адміністратора | створіть іншого адміністратора через `CD_ADMIN_*` у порожній БД або змініть хеш у MySQL |

## 10. Windows-середовища (наступний етап)

Windows не працює як контейнер Docker, тому потрібна віртуальна машина: KVM (`virt-manager`) або Proxmox VE.
План: шаблонна ВМ Windows → швидкі клони для студентів → доступ через RDP, переданий у браузер Apache Guacamole.
У порталі для цього додається новий драйвер (`portal/app/drivers/`) з тими самими методами, що й Docker-драйвер.
Перед стартом перевірте освітні умови ліцензування Microsoft. До того часу можна обмежитися Linux-середовищами.
