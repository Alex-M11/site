# Хмарний робочий стіл — версія для Windows (CloudDesktop.exe)

Портал на одному комп'ютері: для знайомства з проєктом, демонстрації на захисті або невеликого класу.
Для коледжу з десятками студентів використовуйте серверну версію (Linux, `docker compose`, див. README проєкту).

## Запуск

1. Двічі клацніть **CloudDesktop.exe**. Встановлювати нічого не потрібно.
   Windows SmartScreen може попередити про невідомого видавця: **Докладніше → Виконати однаково**.
2. Відкриється браузер з порталом, а біля годинника з'явиться значок ☁.
   Клацніть по ньому → **Відкрити портал**; там же — **Логіни і паролі**, **Папка з даними**, **Зупинити й вийти**.
3. Акаунти (також у файлі «Логіни і паролі»):

   | Роль | Логін | Пароль |
   |---|---|---|
   | Адміністратор | `admin` | згенерований, див. «Логіни і паролі» |
   | Викладач | `teacher` | `Teacher123` |
   | Студент | `student1` | `Student123` |
   | Студент іншої групи | `student3` | `Student123` |

## Два режими

* **Демо** (Docker не встановлено): портал працює повністю — каталог, завдання, здача робіт, автоперевірка,
  кабінети викладача й адміністратора, — а замість робочого столу показано заглушку.
* **Справжні робочі столи** (Ubuntu, Kali Linux, VS Code у браузері): встановіть
  [Docker Desktop](https://www.docker.com/products/docker-desktop/) з WSL 2, запустіть його
  (режим **Linux-контейнерів** — за замовчуванням) і перезапустіть CloudDesktop.exe.
  Перший запуск кожного середовища завантажує образ на 3–6 ГБ — це займе кілька хвилин.
  Кожен відкритий стіл потребує ≈1–1,5 ГБ оперативної пам'яті; на ПК з 16 ГБ комфортно працюють 3–5 столів.

## Де дані

`%LOCALAPPDATA%\CloudDesktop` (вставте в адресний рядок Провідника):
база (`portal.db`), «Мої файли» студентів і здані роботи (`storage`), журнал роботи (`portal.log`).
Щоб почати з чистого аркуша — закрийте програму і видаліть цю папку.

## Обмеження порівняно з серверною версією

* Портал доступний лише на цьому комп'ютері (`http://127.0.0.1:8000`), без HTTPS — він не відкритий у мережу.
* Немає брандмауера між столами й локальною мережею (на сервері це робить `scripts/firewall.sh`).
* Образи `college/mysql-desktop` і `college/dev-desktop` збираються лише на Linux; тут — готові образи Kasm.
* Під час закриття програми всі запущені столи зупиняються (файли зберігаються).

## Параметри запуску (для досвідчених)

`CloudDesktop.exe --demo` — не використовувати Docker; `--port 8100` — інший порт; `--no-browser` — не відкривати браузер.

## Як зібрати .exe самостійно

На Windows з Python 3.12:

```powershell
cd cloud-desktop\portal
pip install -r windows\requirements-windows.txt
pyinstaller --noconfirm windows\CloudDesktop.spec
# результат: dist\CloudDesktop.exe
```

Або автоматично: кожен push у репозиторій запускає GitHub Actions (`.github/workflows/windows-exe.yml`),
який збирає .exe на Windows, перевіряє його запуск і викладає в Actions → Artifacts.
